## 自动化响应与 exactly-once 结论

3.5.19 与 4.x 的体感差异主要来自等待策略和失败状态处理，不是 WinForms 架构本身。

当前 3.5.19 策略：

1. Gameflow 事件到达后立即评估，不在首次动作前人为 sleep。
2. Lobby 正常 POST 成功后提交 membership fingerprint，同一稳定 Lobby 不重复开始匹配。
3. POST 明确失败或 transport 返回 null 时，不立即假定“完全没生效”。先读取一次权威 search state：
   - `isCurrentlyInQueue=true`：说明写入已经生效或队列已存在，提交 fingerprint，停止重试；
   - false / 缺失 / 无响应：保留 fingerprint 空状态，下一次 3s observer 可以重试。
4. 这次 reconciliation 只发生在失败/模糊写之后，正常成功路径不增加网络往返，因此不会把刚修掉的响应延迟重新加回来。
5. ReadyCheck 仍按一个 episode 一次 accept 的更保守语义处理，避免短时状态下形成重复写洪水。

## 自动隐藏行为契约

`GameStart` / `InProgress` / `Reconnect` / `WatchInProgress` 均映射为 `LeagueActivityLevel.InGame`。

- 悬浮球/桌宠进入游戏前可见：Gameflow 获得 hide ownership，隐藏后在离开 InGame 时恢复。
- 用户原本已隐藏：Gameflow 不获得恢复 ownership，赛后不强制显示。
- LCU 临时不可连接时，3.5 `LeagueDashboardPhaseService` 会检查 `League of Legends` 游戏进程；游戏进程仍存在则 activity 继续保持 InGame，降低客户端断连导致桌面入口过早恢复的风险。
- VPetHost 正在后台启动时，hide/show 仍会写入 desired visibility；连接后按最新 desired state 执行。
- 托盘继续保留，用户显式从托盘/二次启动打开控制中心属于主动操作，不等同于自动重新显示桌面悬浮入口。

## UI 修复说明

### 主控面板残影

用户 2026-09-05 提供的实机视频显示的是紧凑主控面板关闭/重开后桌面留下横条/局部旧面板碎片。这和导航按钮文字自身重绘残影是两条独立链路。

`CompactMenuForm` 原始主题窗口基准高 680，`DesktopLauncherEnhancer` 最终把它裁为约 236。现在 `MainForm` 在首次定位和 `Show()` 之前就执行 enhancer，因此 Windows 不再先合成一帧旧全高窗口再缩短。

### Mayhem

继续保留现有 `MayhemAutomaticGuideService` 的本地缓存、并行 fan-out、有界等待和 fail-soft。此次只修显示层：百分比单位、可访问高度、滚动、tooltip、装备/强化展示容量。没有为了“借鉴 4.x”重写数据服务。

## 自动回归覆盖

`LeagueMatchmakingAutomationSmokeTest` 当前覆盖：

- Lobby 第一次 POST 前 `FakeClock.DelayCalls == 0`；
- ReadyCheck 第一次 accept 前 `FakeClock.DelayCalls == 0`；
- 同一 Lobby 成功后 exactly-once；
- 真失败后允许再次尝试，成功后再 fence；
- 模糊/失败写后若权威 `isCurrentlyInQueue=true`，则认定 postcondition 已成立并阻止第二次 POST；
- Tencent Lobby/ReadyCheck 缺少可选字段时仍保持兼容；
- 非目标 phase 零写入。

`LeagueDashboardSmokeTest` 当前覆盖：

- disconnected/null cadence = 3 秒；
- Queueing cadence = 3 秒；
- 可见入口进入 InGame → Hide；
- 重复 InGame heartbeat → None；
- Gameflow 隐藏的入口离开 InGame → Restore；
- 原本手动隐藏的入口离开 InGame → 不 Restore；
- ChampSelect 百分比契约及 Matchmaking 自动化回归。

`FACM.csproj` 的 CI build 明确执行 `--league-dashboard-test`。
