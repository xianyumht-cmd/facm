## 目标

## 当前自动隐藏行为契约

`GameStart` / `InProgress` / `Reconnect` / `WatchInProgress` 均映射为 `LeagueActivityLevel.InGame`，进入后执行桌面入口抑制。

- 如果悬浮球/桌宠进入游戏前可见：Gameflow 记录 ownership，隐藏它，离开 InGame 后恢复。
- 如果用户进入游戏前本来就把入口隐藏了：Gameflow 不获得恢复 ownership，离开游戏后也不强制显示。
- InGame 期间 PetHost/个性化恢复路径不能通过 `ShowBuiltInBall()` 把默认悬浮球重新拉起。
- VPetHost 使用 IPC Hide/Show，不因为一局游戏退出 PetHost 进程。
- 托盘仍保留；用户主动从托盘打开控制面板属于显式操作，不等同于桌面悬浮入口自动显示。

## 自动化响应结论

3.5.19 与 4.x 的体感差异已经证明主要来自等待策略，而不是 WinForms 本身。

本批不搬 4.x 分层，只做：

1. Gameflow 事件到达后立即评估；
2. 依赖已有 fingerprint / episode fence 防重复；
3. disconnected 探测缩短为 3 秒；
4. 失败时再退回有界 retry，而不是成功路径预先 sleep。

因此预期收益是“更快地开始做正确的事”，而不是提高轮询压力。

## 自动化回归覆盖

`LeagueMatchmakingAutomationSmokeTest` 现在除原有 Tencent 兼容、leader/canStart、fingerprint、ReadyCheck exactly-once 外，新增：

- 进入 Lobby 后第一次 POST 前 `FakeClock.DelayCalls == 0`；
- 进入 ReadyCheck 后第一次 accept 前 `FakeClock.DelayCalls == 0`；
- 每个测试最多等待 1 秒观察异步首次调用，不把真实固定延迟掩盖掉。

`LeagueDashboardSmokeTest` 新增：

- disconnected/null cadence 精确为 3 秒；
- Queueing cadence 精确为 3 秒；
- 可见入口进入 InGame → Hide；
- 重复 InGame heartbeat → None；
- Gameflow 隐藏的入口离开 InGame → Restore；
- 原本手动隐藏的入口离开 InGame → 不 Restore；
- 同一 smoke 同时调用 ChampSelect 百分比契约与 Matchmaking 自动化回归。

`FACM.csproj` 的 CI build 现在明确执行 `--league-dashboard-test`。
