# League Akari v1.5.1 — Version-locked implementation research

## Native historical premade candidate (2026-10-26; Draft #357)

The pinned `ongoing-game/analysis-controller.ts` plus `shared/utils/team-up-calc.ts` infer groups from repeated historical same-team membership, with the default threshold of five games. GGman's `LeaguePlayerDataService` parser captures identity-verified same-team PUUIDs when LCU history includes participant identities and team IDs; `LeaguePremadeInference` deduplicates game IDs, limits input to current-roster same-side players and merges eligible connected pairs without extra network work. The native Dynamic Match Messages workbench now offers selected premade groups, display-name strategies, side filtering, preview and session-guarded sending via `LeaguePremadeMessageFormatter`. Empty evidence is explicitly not proof of an ungrouped lobby. This remains a **partial source candidate**: missing Tencent match identities, regional SGP, full Akari selection and source-data variations, and final game validation are open.

The pinned `data-adapter/analysis/player/single/{jungle,objectives}.ts`, `aggregate/jungle.ts` and `utils/geometry.ts` now supply a native pure `LeagueJungleTimelineAnalysis` candidate. Current coverage includes 14-minute weighted activity, gank lanes, level-3/4 signals, side-aware minute-one first camp and objective counts/times, with deduplicated game-level aggregates. Match summaries retain map, participant, team and Smite metadata. A user-selected current-roster player can now retrieve bounded authenticated LCU game details and `/lol-match-history/v1/game-timelines/{gameId}` data in `LeagueDynamicMessageService.LoadJungleAsync`, with session/roster revalidation. This is not yet an end-to-end jungle preset: native selection/formatting/options/shortcuts/sending and Tencent/SGP live acceptance remain in the mandatory queue.

**Status:** source-backed **full functional-parity backlog** in progress, **not** a claim that all features are implemented in GGman. The owner requires **every functional capability of pinned Akari v1.5.1** to be recreated within GGman's existing lightweight native architecture. Delivery is phased; technical difficulty, missing Tencent-region access or elevated performance cost must produce a tracked implementation/verification dependency, **never a permanent feature exclusion**. This document informs Draft PRs #355/#357 and subsequent work. It does not authorize release, source copying, binary execution or changes to the owner-approved compact UI.

## Compatibility, quality and acceptance rules

### Native per-champion spell preset candidate (2026-10-25; Draft #357)

Exact source references: `src/main/shards/auto-champ-config/{state.ts,auto-config-controller.ts,context.ts}` at `14557723706ccc0e0a9d62c470141d4cb7190fcd`. GGman now records and restores the *currently selected* two summoner spell IDs per champion and queue/position group, with `ranked-default` lookup fallback. Source mode mapping covers `CLASSIC` ranked versus ordinary, `ARAM`, `URF`, `NEXUSBLITZ` and `ULTBOOK`. It saves to bounded local settings (and portable cloud settings), reads the existing authenticated LCU session only in the active ChampSelect phase, and calls the existing guarded, readback-verified spell writer. The already-owned 2-second auto-apply loop serves this optional behavior; there is no second worker. It is **disabled by default**, and automatically applying a saved preset is intentionally exclusive with OP.GG's separate automatic recommendation writer to avoid racing over spell slots.

Current limits: the native loadout editor saves the current ranked lane's spells; `ranked-default` fallback can be loaded from a stored configuration but is not yet directly editable as a generic lane preset. This does not implement Akari's champion-specific **rune** catalog, full champion-config editing, nor proof against a real Tencent client; all remain mandatory parity items. CI smoke fixtures are not a substitute for the owner's eventual consolidated game test.

2. GGman remains native WinForms, lightweight, and based on its existing `LayeredFloatingBall` and approved compact panel. **Never change visual geometry or orb behavior** under the pretext of porting an Akari feature. ### Event-driven private-chat auto-reply (pinned v1.5.1 source review and native candidate)

The pinned `Conversation.type` is a free string, not a `private` enum. The independently inspected [Sentinel message handler](https://github.com/molenzwiebel/Sentinel/blob/2d9760bb6e1f64c15638d57c8a8227f728762f90/Sentinel/Sentinel.cs) distinguishes DMs with `type == "chat"` from `club` and lobby rooms. GGman's native guard requires that direct-chat value and matching conversation ID. It decodes URI segments once, then rejects separators, traversal and residual escapes before composing a route. These source-backed shape checks still require Tencent acceptance.

At `14557723706ccc0e0a9d62c470141d4cb7190fcd`, `src/main/shards/auto-misc/auto-reply-controller.ts` does **not** repeatedly fetch chat history. It listens to LCU URI `/lol-chat/v1/conversations/:fromId/messages/:messageId`, requires `event.data.type === 'chat'`, a non-empty enabled reply, an actual local summoner and an incoming `fromSummonerId` different from the local player's. The optional away-only switch requires current availability `away`. It then calls the typed `chat.chatSend(fromId, text)` client method. In `src/main/shards/league-client/index.ts`, one authenticated local WSS session subscribes with `[5, 'OnJsonApiEvent']`; its message handler dispatches `data[2].uri` from the LCU event envelope. The typed send route is `POST /lol-chat/v1/conversations/{id}/messages` with `body` and chat metadata (`src/shared/http-api-axios-helper/league-client/chat.ts`). This is source inspection, **not** proof of equivalent native GGman behavior or Tencent transport compatibility.

GGman's current Gameflow watcher supplies phase snapshots but no direct incoming chat-message events. Polling private conversation bodies on every Gameflow tick would add sensitive network traffic and still miss short-lived events. The existing `ILeagueLobbyNoticeWriteApi` is explicitly restricted to validated `customGame` room announcements; it is **not** a general-purpose private-chat writer. Native parity therefore requires a shared, lifecycle-scoped authenticated LCU event transport and a separately allowlisted private-message POST capability, with explicit opt-in/default-off controls, message ID de-duplication, sender/self and conversation-type validation, bounded dispatch, careful reconnect/disposal, and never logging chat bodies or credentials. First gate: offline WAMP-envelope/route/cancellation tests and Windows net48 transport build. Final gate: one consolidated user-driven Tencent session, including away-only behavior, no reply loops, no stale-account replies and idle RAM/CPU budget. **Native source candidate now implemented:** `LeagueChatEventStream` + `LeagueAutoReplyController` provide bounded sequential WAMP dispatch, opt-in/away-only settings, cross-reconnect event-ID deduplication, private-room/self/account guards and a session-bound typed POST through the existing writer pool. Local net48, League Dashboard and performance smokes pass; Windows CI and live Tencent acceptance remain separate gates. The follow-up native source moves offline locking onto that same stream, seeds its baseline once after subscribing and removes its per-Gameflow-tick presence GETs. Direct-event smoke passed; current-head CI remains a separate gate.
