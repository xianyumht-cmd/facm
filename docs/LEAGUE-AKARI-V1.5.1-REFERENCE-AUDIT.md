### Event-driven private-chat auto-reply (pinned v1.5.1 source review and native candidate)

The pinned `Conversation.type` is a free string, not a `private` enum. The independently inspected [Sentinel message handler](https://github.com/molenzwiebel/Sentinel/blob/2d9760bb6e1f64c15638d57c8a8227f728762f90/Sentinel/Sentinel.cs) distinguishes DMs with `type == "chat"` from `club` and lobby rooms. GGman's native guard requires that direct-chat value and matching conversation ID. It decodes URI segments once, then rejects separators, traversal and residual escapes before composing a route. These source-backed shape checks still require Tencent acceptance.

At `14557723706ccc0e0a9d62c470141d4cb7190fcd`, `src/main/shards/auto-misc/auto-reply-controller.ts` does **not** repeatedly fetch chat history. It listens to LCU URI `/lol-chat/v1/conversations/:fromId/messages/:messageId`, requires `event.data.type === 'chat'`, a non-empty enabled reply, an actual local summoner and an incoming `fromSummonerId` different from the local player's. The optional away-only switch requires current availability `away`. It then calls the typed `chat.chatSend(fromId, text)` client method. In `src/main/shards/league-client/index.ts`, one authenticated local WSS session subscribes with `[5, 'OnJsonApiEvent']`; its message handler dispatches `data[2].uri` from the LCU event envelope. The typed send route is `POST /lol-chat/v1/conversations/{id}/messages` with `body` and chat metadata (`src/shared/http-api-axios-helper/league-client/chat.ts`). This is source inspection, **not** proof of equivalent native GGman behavior or Tencent transport compatibility.

GGman's current Gameflow watcher supplies phase snapshots but no direct incoming chat-message events. Polling private conversation bodies on every Gameflow tick would add sensitive network traffic and still miss short-lived events. The existing `ILeagueLobbyNoticeWriteApi` is explicitly restricted to validated `customGame` room announcements; it is **not** a general-purpose private-chat writer.
