# GGman 注入能力清单 —— 「大厅本身不具备、只能靠注入拿到」的功能全集

日期：2026-11-28
基线：`dll/ggman_core.c`（已合并 GGman 3.5.90 的本地仓库）
定位：按玩家进入大厅的**真实使用路径**逐节点拆，只收「大厅 UI 不提供 / 客户端进程内才能做」的项。

---

## 0. 先立判定框架：三层边界，别把力气花错地方

LCU（本地 HTTPS + WAMP）是**能力的上限**，大厅 UI 只是这个上限的一小部分出口。所以任何想法先过这三问：

| 层 | 判据 | 结论 | ggman 现有形态 |
|---|---|---|---|
| **L1 LCU 有端点** | `GET/POST /lol-*` 存在 | 不需要注入，外部窗口就能做 | `ggman_core.c` 已经在走这条路（面板 4 页） |
| **L2 UI 物理缺失 / 渲染层才有** | 要在大厅界面里出现按钮、面板、屏蔽元素 | **必须注入**（DOM/CSS 或窗口叠加） | 目前只做到"独立面板"，没进客户端界面 |
| **L3 服务端权威** | 段位、胜负、封禁、惩罚计时 | 注入也改不动，只能触发服务端已允许的路径 | — |

一句话：**L1 已经被吃掉了大半，真正的增量全在 L2**；L3 上的需求要先劝退，否则做一个月发现白干。

### J. 明确做不到的（L3，服务端权威，先劝退）

- 无惩罚返回大厅 / 免惩罚秒退 —— `session/quit` 就是 dodge，惩罚由服务端记
- 改段位 / 隐藏分 / 胜率 / 战绩
- 在对局中使用未拥有英雄/皮肤
- 绕过封禁 / 账号冻结 / 设备风控
- 干预匹配（对手强度、队友质量）
- 修改对局结果、跳过惩罚计时

这七项无论注入多深都只是"客户端显示层"的变化，一旦触发服务端校验就回滚，别立项。

## 6. 一句话结论

**大厅给玩家的 ≈ LCU 能力的 20%，而 ggman 已经把那 20% 之外的 L1（端点层）吃掉了大半。**
真正的增量不在"再找几个端点"，而在把结果**搬进客户端那片界面**：选人页的按钮、大厅的页签、广告的屏蔽、结算的对比表、聊天的留痕。

这五件事全都卡在同一个技术门槛上：**拿到 `CefBrowser` 句柄（I2/I3）**。
它一旦打通，D1/D2/B1/B2/G1 全是"写 JS + 挂节点"，一周能出三四个；打不通，就只能继续用独立的悬浮面板顶。
