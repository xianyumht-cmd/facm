## 1. 长期产品决策

FACM 后续只维护 **3.5.x lightweight**：

- 主程序继续使用 `src/FACM` 的 .NET Framework 4.8 / WinForms 架构。
- 正式 3.5 构建保持轻量单 `FACM.exe`，当前 CI 硬门槛 < 10 MiB。
- `FACM.PetHost` 仍作为可选 VPet 运行时源码保留并 build/self-test，但普通 3.5 EXE **不内嵌 self-contained PetHost bundle**。
- 4.x 只作为功能、状态机、生命周期和故障经验参考，不再继续作为独立产品线。
- 不回灌 WinUI 3、`FACM.App`、`FACM.Core/Infrastructure/Platform.Windows` 分层、CAB、native bootstrapper、`.facm/versions`、4.x migration、.NET 10 self-contained 主程序。
- 4.x 有价值能力必须用 3.5 当前 service/session/WinForms 边界重实现或直接复用 3.5 已有能力。

## 2. 审计纪律

## 4. 已确认并修复的 3.5.19 问题

### 4.1 Mayhem 百分比双缩放

Mayhem model/service 使用 0..100 百分点；ChampSelect 显示层又乘 100，导致 `53.5 -> 5350.0%`。已改为直接格式化，smoke 覆盖 `54.32 -> 54.3%`。

### 4.2 Mayhem 展示不全

问题位于显示层：固定高度、ellipsis、augment list 太小、装备人为截断。已扩大攻略区、AutoScroll、增加行高/tooltip/展示容量；**没有替换 `MayhemAutomaticGuideService` 的缓存、并发、有界等待和 fail-soft。**

### 4.3 导航按钮文字残影

`FacmNavButton` owner-draw 的透明背景 + 极低 alpha idle fill 不能可靠覆盖旧像素。已改成确定性不透明 Surface 绘制，仍需多 DPI 实机 Gate。

### 4.4 紧凑主控面板裁剪残影

用户视频中的横条/旧面板碎片来自另一条链：`CompactMenuForm` 基准高 680，旧路径可能先 show/paint 再裁成约 236。现在在 `PositionMenu()` 和首次 `Show()` 前执行 `DesktopLauncherEnhancer.Apply()`，首帧直接使用最终紧凑 geometry。

## 5. 自动化响应差异结论

3.5 原策略：disconnected 10s、ChampSelect 2s、Queue/ReadyCheck 3s、InGame 10s、其它 5s；另外 Lobby 首次固定 1500ms，ReadyCheck accept 固定 450ms。

4.x 真正值得吸收的是“共享 Gameflow 到达后立即评估 + episode/generation/dedupe”，而不是分层架构。

P1 已：

- disconnected/null 10s → 3s；
- 删除 Lobby 1500ms；
- 删除 ReadyCheck 450ms；
- 保留 3.5 monitor/session 架构。

## 6. 自动寻找 / 自动接受：真失败与模糊结果

只在 POST 前提交 fingerprint/episode 会让真失败永远不重试；只在失败后盲重试又可能在“LCU 已接收、响应丢失”时重复 POST。

自动寻找当前方案：

1. POST 2xx：提交 Lobby fingerprint；
2. response 失败/null：此时才额外读取一次 `/lol-matchmaking/v1/search`；
3. `isCurrentlyInQueue=true`：权威 postcondition 已成立，提交 fingerprint，不重试；
4. false/缺失/读取失败：不消费 fingerprint，既有 3s observer 可再次尝试。

ReadyCheck 当前方案：

1. Gameflow 进入 ReadyCheck 后第一次 accept **立即执行**，没有固定 sleep；
2. POST 2xx：消费本次 ReadyCheck episode，停止；
3. POST 失败/null：先重新读取一次 `/lol-matchmaking/v1/search`；
4. 本地 `playerResponse` 已是 `Accepted` 或 `Declined`：把权威终态视为完成，避免模糊成功后的重复 POST，也不逆转用户显式 Decline；
5. 仍是未响应且 phase 仍为 ReadyCheck：释放 in-flight fence，500ms 后轻量重试；离开 ReadyCheck 立即停止。

正常成功路径没有额外预读，不牺牲响应速度；失败路径才支付 reconciliation 成本。

## 7. InGame 自动隐藏

不移植 4.x Surface state machine。3.5 使用小型 `DesktopEntryGameflowPolicy`：

- `GameStart` / `InProgress` / `Reconnect` / `WatchInProgress` → InGame suppression；
- 第一次进入 suppression 始终发出一次 Hide 动作，因此即使悬浮球/桌宠原本被用户手动隐藏、但用户从托盘/二次启动打开了临时控制中心，该窗口也会在进游戏时关闭；
- restore ownership 仍只取决于进入游戏前球/桌宠是否实际可见，所以“原本手动隐藏”不会在赛后被强制显示；
- repeated InGame heartbeat 不重复发 Hide，因此用户在游戏中**主动**从托盘重新打开控制中心后不会被下一次 heartbeat 强制关掉；
- 复用唯一 `LeagueDashboardModule` / `LeagueGameflowMonitor`；
- LCU 不可连接但 `League of Legends` 游戏进程仍存在时继续判 InGame；
- 普通球、Sprite、VPet 非破坏性 hide/show；PetHost 尚未启动完成也记录 desired visibility。
