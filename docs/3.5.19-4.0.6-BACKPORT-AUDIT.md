# FACM 4.0.6 → 3.5.19 轻量回灌审计

状态：**进行中**  
目标分支：`audit/4.0.6-to-3.5.19-20260903`  
生产版本：`3.5.18`（审计期间保持不动）  
4.x 审计基线：**4.0.6 最终生产线**，发布基础 `21105a8143d291373da819b67d86eb29d47c18b3`，最终发布记录 `f688aee01d0f387696ceb88ca4a1b8207943e2c5`。

## 长期产品决策

FACM 后续只维护 **3.5.x**：

- 主程序继续使用 `src/FACM` 的 .NET Framework 4.8 / WinForms 轻量架构。
- 正式分发继续保持单 `FACM.exe`，目标是几 MB 级，不允许为了回灌 4.x 功能重新膨胀到几十/几百 MB。
- 4.x 只作为功能与可靠性参考实现，不再作为独立产品线继续发布。
- 不回灌 WinUI 3、`FACM.App` 宿主、CAB、native bootstrapper、4.x migration、多运行时安装器、.NET 10 大型 self-contained 发布体系。
- 用户价值功能必须用 3.5 原生 WinForms / net48 方式重新实现或复用现有 3.5 服务。

## 基线事实

`v3.5.17` 与 `v4.0.0` 曾指向同一个源码提交 `09888896ae4273a0d4d5e1b9dd4f159c233f103b`。因此大量 4.0 用户功能在同一仓库里本来就已经有 legacy 3.5 等价实现；不能按版本号假设“4.0 的东西 3.5 都没有”。

从 `09888896` 到 4.0.6 发布基础 `21105a8` 的后续 27 个提交主要是 4.x 分发、维护页和更新链修正。4.0.6 最后明确的功能修复是维护页清理确认执行和模块化更新链；其中后者属于明确拒绝回灌的 4.x 发布体系。

## 已落地的第一批回灌

### 1. settings.ini 原子保存

提交：

- `262e6e07f7d0e20a71001a21464d8d7abc538702` — `fix(settings): make 3.5 settings writes atomic`
- `e4c3719b3fabbe1304dea195a1e6d62d6c299ee0` — `test(settings): cover atomic 3.5 settings replacement`

实现原则：

1. 保持现有 INI 格式和所有字段，不引入 Settings2 JSON。
2. 同目录创建唯一临时文件。
3. 使用 `FileOptions.WriteThrough` 写入，`Flush(true)` 落盘。
4. 已有文件优先 `File.Replace`；兼容 fallback 使用 Windows `MoveFileEx(REPLACE_EXISTING | WRITE_THROUGH)`。
5. 不存在目标文件时也用同目录 write-through move 提交。
6. 进程内写入用静态锁串行化，降低多个功能同时保存造成 lost-update / half-write 的风险。
7. smoke 覆盖首次写入、二次替换和临时文件清理。

## 3.5.19 第一阶段产品目标

### P0 — ChampSelect 轻量助手

不移植 4.x Morphing MainWindow，而是在现有 3.5 League 服务之上做 WinForms 小型 TopMost 助手：

- 进入 ChampSelect 时自动出现；离开后自动关闭。
- 默认只显示小型 Bench strip，不再强制自动弹出 820×620 的完整实时对局窗口。
- Bench 候选继续复用现有 `LeagueBenchQuickPickService`，不新建第二套 LCU writer。
- 自动识别本地当前英雄。
- 自动加载 Mayhem/ARAM 攻略：技能顺序、召唤师技能、出装、强化符文排行和图标。
- 自动攻略只读，不自动写符文/技能/装备配置。
- 自动攻略失败不能影响 Bench 换人。
- 用户仍可从完整 League Hub 手动打开完整实时对局与手动 Mayhem 查询。
- 同一 ChampSelect episode 用户手动关闭后不骚扰式重新弹出。

### P1 — 诊断与可靠性

- 轻量 Diagnostics Center / 结构化日志查看器。
- 支持导出本地诊断包，方便售后排障。
- 继续逐条审计 4.x Batch D/I/K 的 League cancellation / teardown / repeated lifecycle 修复是否在 3.5 需要等价补强。
- 评估简单、安全的 `settings.ini` LKG 恢复，不引入 4.x Settings2 架构。

### P2 — 可选高精度桌宠

只有在不影响核心单 EXE 体积时才保留：

- 主 `FACM.exe` 不内嵌几十 MB self-contained PetHost。
- 可采用用户主动启用时按需下载/缓存、或独立可选组件。
- 必须有 SHA-256 / 版本 identity / cache reuse / fail-soft 回默认悬浮球。

## 明确禁止回流

以下内容即使 4.0.6 中已经实现，也不进入 3.5.19：

- `FACM.App` WinUI 宿主
- `FACM.Core` / `FACM.Infrastructure` / `FACM.Platform.Windows` 作为新的运行时依赖层
- native bootstrapper
- CAB 分发
- 4.x manifest / component manifest / detached signature 分发体系
- `.facm/versions/...` 多版本运行目录
- 3.x → 4.x migration bridge
- .NET 10 self-contained 主程序
- 把 FlyingHost / PetHost 大运行时重新嵌进 3.5 主 EXE

允许参考其中的算法、状态机和可靠性边界，但最终代码必须服务于现有轻量 3.5 架构。

## 发布门禁

3.5.19 不会因为“代码写完”直接推生产。至少需要：

1. Windows Actions Release 构建通过。
2. `--facm-host-test` 和现有 League / performance / update smoke 全绿。
3. 新 ChampSelect 助手有独立 deterministic smoke。
4. 实机验证普通匹配 ChampSelect、ARAM/Mayhem Bench、离开 ChampSelect 自动关闭、LCU 不在线时 fail-soft。
5. `FACM.exe` 保持轻量；核心 EXE 硬门禁继续 `< 10 MB`，目标仍为约 2 MB 量级。
6. 不改变生产 `online/version.json`，直到候选 EXE、签名和 SHA 完整验收。

本文件是 4.0.6 → 3.5.x 回灌的 canonical 审计账；后续每确认一个差异或完成一个回灌，都必须同步更新。
