## 当前结论：桌宠路线再次调整

用户已经实机验证 Build #281、#288、#295。

当前 FACM 原生 Sprite 桌宠已经证明“功能可用”，但视觉和运动仍未达到成品要求。下一轮聊天不要继续在现有 `SpritePetWindow` 上小修小补，应直接以 **真实感上限最高** 为目标重做桌宠运行层。

用户明确允许：

1. **迁移 FACM 技术栈**，不需要因为现有程序体积小而坚持 .NET Framework 4.8 / WinForms。
2. 桌宠素材 **不要求可商用**；FACM 本身不是商用项目，可以使用明确允许非商业使用的高质量素材。
3. **不加入 Canva 连接器依赖**。
4. 优先追求真实感、运动自然度和成熟产品体验，而不是继续追求最小 EXE。
5. 可以使用成熟开源桌宠引擎，也可以拆成独立 PetHost；不要为了“纯自研”牺牲体验。

## 最新实机反馈：Build #295

Build #295 已把桌宠从静态 Emoji/PNG 平移升级为多帧 Sprite Sheet，并通过 CI，但用户实机反馈仍然不合格：

- 大部分宠物素材分辨率太低，放大后像素感明显。
- 宠物移动过程中会偶发“闪一下”：瞬间消失，然后重新出现。
- 存在“倒着走”“倒着飞”的方向错误。
- 即使有动画帧，整体仍像“一个透明背景图片在桌面随机平移”，没有角色在主动移动的感觉。
- 帧率已经比最初版本高，但仍缺乏真实运动感。
- 用户认为从程序整体体验看，当前桌宠仍明显像实验品，不像成熟桌面宠物。

因此：**不要再把“多帧 Sprite + WinForms 窗口平移”当成最终架构。**

## 下一轮聊天的第一优先级

### 目标

不要继续修 #295 的闪烁/倒走作为最终方案。下一轮直接尝试 **真实感上限最高的成熟桌宠架构**。

### 首选方向：VPet Core / VPet 运行层

下一轮优先认真评估并落地 **VPet Core / VPet-Simulator.Windows** 路线，因为其真实桌宠能力上限明显高于当前手搓 Sprite 窗口，包括更完整的动作状态、交互、移动行为和成熟动画体系。

用户已经允许迁移 FACM，因此不要被当前 `.NET Framework 4.8 + WinForms` 限制住。

建议优先比较两种落地方式：

1. **FACM 整体迁移到现代 .NET / WPF**，直接接 VPet Core；
2. **保留 FACM 主程序，新增独立 `FACM.PetHost`**（现代 .NET / WPF），由 FACM 通过 IPC/本地 API 控制 PetHost。

选择标准不是“改动最少”，而是：

- 动作真实；
- 不闪烁；
- 方向正确；
- 有 Idle / Walk / Run / Turn 等状态机；
- 动画与位移同步，不是窗口匀速滑动；
- 透明窗口稳定；
- 可扩展高分辨率宠物；
- 用户安装/使用步骤尽量简单。

如果 VPet Core 因技术或许可证/资源结构原因无法快速落地，再比较 OpenPet 或其他成熟开源运行时。**不要先回退到自己重新手搓 WinForms 引擎。**

## 素材策略

下一轮素材筛选规则：

- 不再限制“可商用”。
- 可以使用明确允许 **个人/非商业使用** 的高质量动画素材。
- 仍然必须尊重作者许可证；若明确禁止再分发，不要直接打包进 FACM，可考虑运行时从作者公开地址下载，或换素材。
- 优先高分辨率、多动作、多方向、完整 Sprite/Live2D/Spine/模型资源。
- 不再使用 Noto Emoji、16×16 放大这类低质量资源作为正式宠物。
- `docs/ANIMAL-PET-ASSETS.md` 继续记录来源/作者/许可证。

## 下一轮建议执行顺序

1. 拉取/审查 VPet 当前源码、Core 架构、目标框架、许可证和最小可嵌入/可宿主方案。
2. 判断“整体迁移 FACM”与“独立 PetHost”哪条更快得到真实桌宠。
3. 先只做 **1 只高质量宠物**，不要一开始堆数量。
4. 必须实现并实机/CI 可验证：Idle、Walk/Run、Turn、拖动、复位、透明窗口、方向正确、连续运行不闪。
5. 再做第二只：优先蜘蛛/苍蝇这类运动视觉明显的宠物，用于验证方向和动画状态机。
6. 用户认可真实感后，再迁移猫、狗和其他宠物。
7. 最后才清理/删除旧 `SpritePetWindow` 实验代码。

## 产品验收标准

下一版不要仅以“能跑”作为完成。至少满足：

- 用户一眼看上去不是“图片在桌面滑”。
- 起步、移动、转身、停下有连续动作逻辑。
- 朝向与移动方向一致，不允许倒着走/飞。
- 连续运行至少几分钟无瞬间透明/闪烁。
- 高分辨率素材不因窗口放大变成明显马赛克。
- 宠物不会完全跑出屏幕；托盘“宠物复位”仍可一键召回。
- FACM 主程序与 Mayhem、主题、工具等既有功能不被迁移破坏。

- 不要重新尝试 Desktop Homunculus 的 DX12/Vulkan/NVIDIA 参数。
- 不要使用 Canva 作为桌宠运行资源依赖。
- 不要为了 EXE 体积小而拒绝成熟框架或资源包。
