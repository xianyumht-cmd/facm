## 6. 已失败方案、失败原因、不要重复路线

### 失败路线 A：FACM semantic Brush alias → 直接 ThemeResource

第一轮假设：

FACM semantic Brush 使用 `StaticResource` 二次别名到 WinUI ThemeResource，可能出现“编译能过、Win10 runtime 解析失败”。

实施：

- MainWindow 平台 Brush 改成直接 `{ThemeResource ...}`
- `FacmControls.xaml` 中部分颜色资源也改为直接平台 ThemeResource

候选：

- head `6aeffa269033526a0d9b6b9c28ed6b84a43afd2e`
- Foundation / Windows Build / UI Text 全绿
- artifact id `9668989230`
- artifact digest `sha256:194ef479949060071d582a52f3d969342ca88daf8f314d12ed4c084bb86d9bea`

真实结果：

**失败。** Win10 22H2 仍然 `launch-XamlParseException`。

结论：

> 不要再重复“把 FACM Brush 改成 ThemeResource / StaticResource 互换”作为主线。它不是根因。

### 失败路线 B：把 MainWindow 做成零 FACM 自定义资源依赖的二分版

第二轮假设：

如果完全去掉 MainWindow 的 FACM 自定义 Style / ThemeResource / Brush，只保留 WinUI 默认控件，若能启动则说明 Design System 自定义资源有问题。

实施：

- MainWindow 临时去掉 FACM Style/Brush/ThemeResource
- 保留四入口、NavigationView、Frame、LOL/Diagnostics 基本结构和命名
- 新增针对 `InitializeComponent()` / MainWindow 构造的 XAML failure 文件
- 更新 source gate 允许这一临时真实机器诊断模式，同时仍保留结构/可访问性合同

候选：

- head `15fb9d80298e64b27f4d9edbcaf21cb609501caf`
- artifact id `9669531909`
- 全 CI 绿

真实结果：

**仍失败。**

但这次得到精确错误：

```text
Cannot find a Resource with the Name/Key TabViewButtonBackground
HRESULT 0x802B000A
```

结论：

> 这已经强烈反证“FACM 自定义 Design System 是唯一根因”。即使 MainWindow 不直接使用 FACM Style，默认 WinUI 控件模板仍找不到 WinUI 自身资源键。下一步应该检查 WinUI 控件资源字典初始化，而不是继续删 MainWindow 元素。

### 失败路线 C：AppDomain UnhandledException 兜底观察器单独抓错误

新增过 `App.StartupFailureObserver.cs`，监听 AppDomain 未处理异常，尝试写：

`runtime/recovery/launch-failure.txt`

真实第一次复测没有出现该文件。

原因：

WinUI `XamlParseException` 在当前启动链被 `OnLaunched` try/catch 观察后重新抛出，且 AppDomain observer 并不能稳定提供我们需要的详细 XAML 诊断。

后续已经用**MainWindow 定向捕获**解决，成功生成：

`runtime/recovery/main-window-xaml-failure.txt`

所以：

> 不要再把 AppDomain observer 作为主要定位手段。保留它做 defense-in-depth 可以，但真正有效的是 MainWindow/InitializeComponent 定向记录。

### 不要做的其它路线

## 7. 当前最可能根因：缺少 XamlControlsResources

这是新对话必须优先验证的方向。

事实链：

1. 原正式 MainWindow：`XamlParseException`
2. FACM ThemeResource 直取版：仍 `XamlParseException`
3. 零 FACM 自定义样式 MainWindow：仍 `XamlParseException`
4. 定向 failure detail 明确：
   `Cannot find a Resource with the Name/Key TabViewButtonBackground`
5. 当前 `App.xaml` 的 MergedDictionaries 只有：
   - `FacmTokens.xaml`
   - `FacmControls.xaml`
6. 当前 `App.xaml` 没有显式：
   `XamlControlsResources`

因此最高概率修复：

```xml
<Application
    x:Class="FACM.App.App"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    xmlns:controls="using:Microsoft.UI.Xaml.Controls">
    <Application.Resources>
        <ResourceDictionary>
            <ResourceDictionary.MergedDictionaries>
                <controls:XamlControlsResources />
                <ResourceDictionary Source="ms-appx:///Themes/FacmTokens.xaml" />
                <ResourceDictionary Source="ms-appx:///Themes/FacmControls.xaml" />
            </ResourceDictionary.MergedDictionaries>
        </ResourceDictionary>
    </Application.Resources>
</Application>
```

或等价合法 WinUI 3 写法。

新对话不要直接相信示例语法；**先根据 Windows App SDK 2.4 / WinUI 3 当前项目语法确认正确 XAML 写法，再提交。**

建议同时新增 source gate：

- `App.xaml` 必须存在 exactly one `XamlControlsResources`
- 它必须排在 FACM 自定义 dictionaries 之前
- 不能因为修启动删掉原 `FacmTokens/FacmControls`

如果此修复真机启动成功，再逐层恢复二分版临时去掉的 FACM Style，而不是把诊断版作为最终 UI。

## 发布包默认配置

用户计划把 `settings.ini` 直接放到发布压缩包根目录，与 `FACM.exe` 同级。

`AppSettings` 当前读取以下 8 个键：

```ini
BallX=-2147483648
BallY=-2147483648
GamePath=
AutoUpdateEnabled=True
LastAnnouncementId=
ThemeId=aurora-night
PetStyleId=vpet
AnimalPetEnabled=True
```

发布建议：

- `BallX/BallY=-2147483648`：表示未保存过位置，让每台电脑按自己的主屏幕选择默认悬浮位置，不要把开发机的 `558/115` 等实际坐标带进发布包；
- `GamePath=`：保持空，让用户自动识别/选择；
- `AutoUpdateEnabled=True`：默认启用更新检查；
- `LastAnnouncementId=`：发布包保持空；
- `ThemeId=aurora-night`：有效主题 ID，对应“极光夜幕”；
- `PetStyleId=vpet` + `AnimalPetEnabled=True`：**首次启动 FACM 会自动启动 PetHost，并在 `runtime\pethost` 没有完整资源时联网自动下载/补齐 VPet 桌宠资源，随后生成动作缓存并显示桌宠。**

如果是覆盖升级且 `runtime\pethost` 已有完整资源，则不会整批重复下载，只会按现有校验/续传逻辑补缺失文件。

发布包推荐根目录：

```text
FACM\
├─ FACM.exe
├─ settings.ini
├─ ui-text.ini        # 可选：随包提供用户想要的默认文案
├─ PetHost\
└─ ...
```
