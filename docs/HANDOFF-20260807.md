## 本轮已完成

### 1. 默认内置高级 3D 风格悬浮球

已完成：

- `MainForm` 不再是 1x1 屏幕外透明入口。
- 启动后立即显示 88x88 内置悬浮球，不依赖桌宠引擎和 VRM 资源。
- GDI+ 高质量渐变、辉光、轨道、核心高光和动态效果，作为独立默认入口。
- 左键点击打开控制面板。
- 左键拖动可自由移动，松开后保存坐标；重启恢复。
- 右键打开常用菜单。
- 控制面板 10 套主题不影响悬浮球。
- 仅用户主动进入桌面宠物并成功启用后才隐藏默认悬浮球。
- 桌宠选择取消、安装失败、下载失败、启动失败、恢复失败时都会保留/恢复默认悬浮球。
- 新增 `--floating-ball-test`；CI 会实际创建 `MainForm` 并离屏绘制悬浮球，检查窗口和可见像素。

关键文件：

- `src/FACM/MainForm.cs`
- `src/FACM/FloatingBallSmokeTest.cs`

### 2. 桌宠 MSI 安装后找不到 exe

已完成：

- 新增 `DesktopHomunculusLocator`，不再只硬编码一个 exe 名。
- 联合探测：
  - 当前/安装后进程路径；
  - HKCU/HKLM 卸载注册表；
  - Registry64 / Registry32；
  - `InstallLocation`；
  - `DisplayIcon`；
  - `UninstallString`；
  - LocalAppData / Program Files / Program Files (x86)；
  - 开始菜单快捷方式目标；
  - 产品相关目录递归 exe 搜索。
- 排除卸载器、更新器、`msiexec.exe` 等错误候选。
- MSI 返回成功后继续等待真实 exe 出现，不能只以 msiexec 返回码作为成功条件。
- 找到后实际启动，再等待本地 API 就绪；失败会重新探测并重试。
- 用户界面只显示简洁提示，详细路径和异常写日志。
- 保留取消。
- 新增 `--pet-locator-test`，CI 会在 LocalAppData/Programs 下构造可重复的模拟安装目录验证定位与等待逻辑。

关键文件：

- `src/FACM/Pets/DesktopHomunculusLocator.cs`
- `src/FACM/Pets/DesktopHomunculusManager.cs`
- `src/FACM/Pets/DesktopHomunculusLocatorSmokeTest.cs`

### 4. 海斗数据与图片资源

已核实并调整：

- Riot 官方 Data Dragon 可提供英雄、技能、装备、中文静态数据、英雄头像和原画。
- Riot 官方接口不直接提供当前 Mayhem 聚合胜率/排行/完整推荐榜，因此统计层仍需现有聚合页面数据。
- 图片/静态资料层改为 Riot Data Dragon 优先。
- 本机 League Client `lol-game-data` 作为补充来源，尤其用于强化等客户端静态资源。
- CommunityDragon 仅作为无法从本机客户端读取相关静态资源时的后备镜像，不再把它描述成 Riot 官方接口。
- OP.GG / ARAMMayhem 等来源细节保留在内部服务和日志，不在普通用户最终图片卡中展示。

关键文件：

- `src/FACM/Mayhem/RiotDataDragonService.cs`
- `src/FACM/Mayhem/RiotGameDataService.cs`
- `src/FACM/Mayhem/OpggMayhemService.cs`

### 5. 查询性能、取消和缓存

已完成：

- 排行/构建来源并行请求。
- 整个用户查询流程统一约 8 秒硬上限，包括静态图片资料和最终卡片生成。
- 用户点击“取消”或关闭窗口会取消请求。
- 图片下载并行。
- 图片内存缓存 10 分钟。
- 图片磁盘缓存 6 小时，目录：程序目录 `cache/mayhem-images`，无权限时回退临时目录。
- 查询结果缓存 10 分钟。
- 图片缓存有数量和过期清理，避免无限增长。

关键文件：

- `src/FACM/Mayhem/MayhemImageCache.cs`
- `src/FACM/Mayhem/MayhemLookupForm.cs`

### 6. 在线 version/announcement 启动 404

现状：

- `main` 当前仍未包含 `online/version.json` 和 `online/announcement.json`，所以 PR 合并前访问 main raw 地址确实是 404。
- 功能分支包含这两个文件。
- `OnlineService` 保留 main -> preview fallback，但成功回退时不再把预发布阶段的预期 404 写成普通启动噪音。
- PR 合并后 main 会得到 `online/*` 文件，主地址即可直接成功。
- 如果主/预览两个地址都失败，用户只看到简洁的“暂时无法读取更新信息，请稍后重试”。

关键文件：
