日期：2026-09-05  
主产品线：FACM 3.5.19（WinForms / net48 / 轻量单 EXE）  
参考产品线：FACM 4.x（仅用于提取最佳实践，完成后退出当前仓库工作树）  
关联：Draft PR #241、`docs/3.5.19-4.0.6-BACKPORT-AUDIT.md`、`docs/3.5.19-P1-BACKPORT-STATUS-2026-09-05.md`

## 1. 清理原则

本清单用于在 3.5.19 回灌完成并通过实机 Gate 后，删除当前工作树中的 4.x-only 实现、构建链、迁移链、探针、证据和历史操作文档，使仓库重新以 3.5.19 为唯一产品主线。

这里的“删除 4.x”指删除当前分支/未来 `main` 工作树中的 4.x-only 文件，不重写 Git 历史。历史提交仍可从 Git 追溯。Release/tag/远端历史分支属于第二层清理，不与源码删除混在同一个未经验证的动作中。

分类含义：

- **RETAIN**：3.5.19 当前构建、运行、更新、测试或文档链仍依赖。
- **DELETE AFTER GATE**：已确认只服务 4.x，实机 Gate 通过后可删除。
- **MIGRATE / CONSOLIDATE**：文件本身可能保留，但内容必须从 4.x 当前态改成 3.5.19 当前态，或把仍有价值的结论吸收到 3.5.19 文档后再删历史文档。
- **REVIEW**：不是明显的 4.x-only 文件，删除前需要再确认实际引用。

## 10. 3.5.19 当前主控面板残影任务已纳入清理前 Gate

用户提供的视频显示的是“旧全高主控面板裁剪后，关闭/重开时桌面留横条或局部旧面板碎片”，与 `FacmNavButton` 文字残影不同。

代码根因路径已经按 3.5.19 实际实现处理：`CompactMenuForm` 基准高度 680，而 `DesktopLauncherEnhancer` 把它裁为紧凑高度；以前增强/crop 可发生在首次显示链之后。本批已在 `MainForm.EnsureMenuOpenAndActive()` 中把 `DesktopLauncherEnhancer.Apply(_menu)` 提前到 `PositionMenu()` 和 `_menu.Show()` 之前，使 Windows 首帧直接看到最终紧凑窗口尺寸。

因此 4.x 清理前人工 Gate 增加：连续打开/关闭主控面板、悬浮球拖动导致菜单关闭、主题切换后重开、桌面被其它窗口覆盖后恢复，均不得留下裁剪残影。

## 11. 真正执行删除时的顺序

1. 先完成 PR #241 Windows 10 实机 Gate；失败则继续修 3.5.19，**不删 4.x**。
2. 将仍有效的 4.x 最佳实践结论收束到 backport audit / 3.5 canonical docs。
3. 先删除 4.x workflows/probes/scripts，避免后续删除源码后 CI 仍调用不存在路径。
4. 删除 `FACM4.sln`、4.x-only projects、native bootstrapper、FlyingHost、WinUI prototype。
5. 删除 `online/facm4-version.json`、4.x evidence、4.x root BAT 和历史 4.x docs。
6. 重写 `README.md` / `PROJECT_STATE.md` / `ARCHITECTURE.md` / `OPERATIONS.md` 等 canonical 文档为 3.5.19 current truth。
7. 搜索工作树中的 `FACM4.sln`、`FACM.App`、`FACM.Core`、`FACM.Infrastructure`、`FACM.Platform.Windows`、`FACM.Bootstrapper`、`FACM.FlyingHost`、`facm4-version.json`、`BOOT3`、`FACM 4.0` 残留引用；逐项判断是 stale doc 还是兼容说明。
8. 重新运行 `FACM Windows Build`、`FACM UI Text Contract` 和 Mayhem source probe；确认 3.5 release workflow 的引用完整。
9. 只在上述全绿后合并到 `main`。
10. 源码主线稳定后，再单独审查远端 4.x Release/tag/临时 branch 是否应删除；该动作不与源树清理混做。
