# 2026-08-25 海斗紧凑海符卡交接

## 目标

Issue #165：FACM「海斗攻略」对齐 lolapisevers 2026-08-24/25 已上线的紧凑海符榜思路。参考的是信息结构与经过验证的数据投影，不复制服务端运行时。

后续 3.5.8 在 3.5.7 实机截图基础上继续把结果从“数据展示卡”收束为“实战决策卡”：重要结论必须在首屏可读，关键装备不能只依赖远程图标，所有结论继续受真实上游字段约束。

## 3.5.7 已发布基线

- `MayhemCardRenderer` 从固定 `1260×1540` 大卡改为约 `840px` 宽的动态高密度卡。
- 信息顺序：英雄概览 → 基础 ARAM / Mayhem 两层平衡 → 出装与技能 → 按稀有度分组强化 → 选符方向。
- 强化展示收敛为 TOP 10；选符方向由单强化的真实胜率/选择率推导，并强制三个方向不重复强化，不声称是三符组合胜率。
- 新增详细出装模型：两套核心构筑、出门装、鞋子、召唤师技能、技能优先级。
- `MayhemBuildDetailsService` 使用既有 `LeaguePublicDataTransport` 读取同一 OP.GG build 页面，遵守 allowlist、15 分钟缓存、stale fallback；失败时回退到 FACM 原有核心装备/技能数据，不阻断海斗查询。
- 图片资产不再加载 splash / TOP5 头像等非必要装饰；首轮英雄/强化/技能图标约 1.15 秒总预算，详细出装新增图标约 0.55 秒补充预算，超时直接占位。
- 仍复用 `MayhemImageCache` 的内存/便携磁盘缓存，不新增第二套图片缓存。
- 上述基线已随 FACM 3.5.7 正式发布；用户提供了 3.5.7 亚索海斗结果实机截图，确认真实输出链可用，同时暴露出“首屏结论不够直接、图标失败时装备只剩单字占位”的产品问题。

## 3.5.8 决策助手改进

- 顶部新增「先看结论」三栏，只从已验证字段投影：`强度位置 / 首看强化 / 首套核心`。
- 强度位置只使用现有 `Tier / Rank / WinRate`；不额外发明英雄玩法标签。
- 首看强化在存在单符胜率/选择率时使用现有稳定评分逻辑；统计缺失时只退回榜单首位，不伪造胜率。
- 两套核心出装同时显示装备名称与图标；出门、鞋子、召唤师技能也保留文字名称，因此图片超时/被拦时仍可读。
- 强化卡把 `优先级 #N` 提到显眼位置，同时保留真实胜率、热度、样本和效果说明。
- 选符方向改成玩家语言：`稳定赢法 / 高上限玩法 / 热门好上手`，但底层排序语义不变。
- 页脚免责声明缩短并弱化，但继续明确“单符统计不代表三符组合胜率”。
- 不增加新的公网请求、常驻 Timer、后台预取或图片预算；性能边界沿用 3.5.7。

## 与 lolapisevers 的边界

参考并复用了以下稳定思路：840px 紧凑布局、TOP10、两套核心出装、出门/鞋子/召唤师/技能、按稀有度两列卡片、单符三方向决策、远程图标总预算。

FACM 不复用服务端 FastAPI/Pillow 缓存实现，也不伪造 lolapisevers 的 `180KB` HTTP 图片响应约束。FACM 是本地 WinForms 位图，重点是减少画布与无效资产、缩短首次绘制等待，并保证图片失败时关键文字仍可读。
