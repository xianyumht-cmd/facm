# 事故与修复：大厅卡死

时间：2026-11-25 08:50–09:07
现象：用户在客户端里"大厅卡死"，点击无响应

---

## 根因（两条叠加）

1. **面板压在客户端交互区上并吞掉点击**
   紧凑卡片默认放在客户端**右下角**，而选人阶段的"锁定/确认"按钮就在右下角。
   命中测试只在按钮/行/标题条返回 `HTCLIENT`，卡片盖住的那块地方，点击永远落到我们的窗口上 → 客户端"点不动"。

2. **我们的消息循环被网络调用阻塞，连"隐藏自己"都做不到**
   `refresh()` 在同一个线程里做多次**同步** WinHTTP 请求（phase、session、换英雄、精通、情报 3 发/次），
   一旦某个请求慢，整个循环停住 → `WM_LBUTTONUP`/`WM_CLOSE` 都排不上队 → 面板一直显形、一直吞点击。
   日志实证：`watchdog: hid panel, loop stalled 4875 ms` —— 循环真的停了近 5 秒。

## 修复（已生效）

| # | 改动 | 说明 |
|---|---|---|
| 1 | **默认只显示 32×32 徽标**（`start_hidden=1`） | 面板默认隐藏，**只有你点徽标才出现**，不可能挡住任何操作 |
| 2 | 阶段自动显示逻辑不再强行弹出面板 | `apply_phase_ui` + 配置重载都尊重 `start_hidden` |
| 3 | **watchdog 线程** | 每 1 秒检查一次；循环停滞 > 4 秒 → 自动隐藏面板并写日志 |
| 4 | **停滞即穿透** | `WM_NCHITTEST` 里：上次 tick 超过 2 秒没完成 → 整窗返回 `HTTRANSPARENT`，点击直接给客户端 |
| 5 | 请求节流 | tick 300ms → **700ms**；选人 session 每 tick 只取 1 次（原来 2 次）；情报抓取 **1 个请求/tick**（原来 3 个）；换英雄轮询 1s → **3s** |
| 6 | HTTP 超时 | WinHTTP 连接/发送/接收 **1.5s** 超时（原来 3s，且无上限保护） |

节流后一次选人阶段的请求量：约 **1.4 请求/秒**（原来峰值 ~10 请求/秒 + 3 次/300ms 的突发）。

## 现在的使用方式

| 想做什么 | 操作 |
|---|---|
| 看信息 | 点顶栏 **G** → 出 272×92 卡片（这时才占用屏幕） |

## 仍未解决 / 注意

- 我们的循环在 LCU 繁忙时仍会短暂停顿（几百毫秒），此时面板会短暂"不响应"，但**不会再吞点击**（穿透 + watchdog 兜底）
- 徽标默认在客户端相对 (404,10)（顶栏，和页签同一行），可以拖动，位置会记忆
- 若再出现整窗卡死，直接 `python tools\agent_procs.py --kill` 立刻解除（我们不在客户端进程里做任何 hook，杀掉只是重载 UI）
